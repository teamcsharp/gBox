# RE4 Switch Mercenaries rooms: collision (SAT) as measured

Ticket #9342 (62a4f454ab2a4ee5). Source: `~/gBox_alt/switch/romfs/010099A00BC1E000/bio4/st4/r400|r402|r403|r404.udas`
(Village, Castle, Base, Waterworld). Tables: `re4-switch-mercs-collision.json` (same folder). Read-only: no game file copied, no code under
`system/gbox` changed, no game session or worker job touched.

## Where the collision is
`gbox.re4_switch_assets.pack_slots(udas)` lists the pack's DAT slots. **Slot 1, extension `SAT`, is the player collision** in all four rooms
(slot sizes in bytes: r400 132,640; r402 116,320; r403 126,944; r404 84,896). Each pack also holds an `EAT` slot (index 14 in all four; enemy
collision, **not parsed here**) and a `CAM`, `LIT`, `SMD` (scene), ... set. That SAT is the *player* collision rests on the PC/GameCube naming given in the ticket; on Switch it was not run against gameplay, so "player" is **not determined** (would be settled by moving the player
into a SAT wall in a live session, which this ticket forbids).

## Record layout (little-endian; measured offsets inside the SAT slot)
| offset | size | field | how obtained |
|---|---|---|---|
| 0x00 | u32 | magic: bytes `80 01 79 ff` (u32 0xff790180) | same in all 4 rooms |
| 0x04 | u32 | 8 (meaning not determined) | same in all 4 |
| 0x08 | u16 | 32 (meaning not determined) | same in all 4 |
| 0x0a | u16 | n_verts | r404 878, r400 1259, r402 1395, r403 1134; vertex block ends exactly where the next block starts |
| 0x0c | u16 | n_normals | 201 / 758 / 677 / 918 (r404, r400, r402, r403) |
| 0x0e | u16 | n_edge_vecs (= 3 x n_tris in every room) | 2925 / 3870 / 3831 / 4506 |
| 0x10 | u16 | 0 | |
| 0x12 | u16 | n_tris | 975 / 1290 / 1277 / 1502 |
| 0x18, 0x1a | u16, u16 | r404 817, 261 (other rooms differ; meaning not determined, header ends at 0x1c) | read with struct `<2I10H` |
| 0x14, 0x16 | u16, u16 | 136,22 (r404), 99,73 (r400), 197,52 (r402), 346,37 (r403): count of the spatial-index tail records (meaning not determined) | |
| 0x1c | 12 x n_verts | f32 x,y,z vertices | normals block that follows is unit vectors, face normals computed from these vertices agree with the stored normal (below) |
| next | 12 x n_normals | f32 unit normals | |
| next | 12 x n_edge_vecs | f32 x3 per triangle edge records (values like +-4070.18 for a 7,400 mm quad in r404; use not determined; not needed for the grid) | |
| `face_off` (r404 0xbbcc, r400 0x11410, r402 0x114d0, r403 0x13384) | 20 x n_tris | triangle: u16 v0,v1,v2 (+0x00..0x05), u16 normal_index (+0x06), u16 x3 edge-vec indices (+0x08..0x0d, all < n_edge_vecs; not simply 3i..3i+2), u16 0 (+0x0e, 0 in every triangle), u32 flags (+0x10; values 0x4000,0x8000,0xc000,0x6000,0xa000,0xe000... meaning not determined) | **found by search**: the only (stride, offset) with all three u16 < n_verts and distinct for every triangle; then stored normal vs geometric normal: min |cos| = 1.0000, 0 degenerate triangles in all four rooms |

(The u16 at +0x0e of a triangle is the 0x0e/0x0f bytes of its record; header field 0x0e above is a different offset: header, not triangle.)

## Axes and frame
* **Up axis is y**: Waterworld floor triangles have stored normal (0,+1,0) and y = 0; the vertex y range is small compared to x and z.
  The horizontal plane is x,z (grid origin/cols are x,z).
* Units: the values are used as millimetres without scaling. Evidence: the 7,400 x 7,400 floor quad at the start of r404, and the
  Village position below (Leon 1,837 tall in the scene per `re4_stage_greybox.py`). Whether 1 unit is exactly 1 mm in SAT is **not
  determined**; a measured player height against a SAT step would settle it.
* **Shared origin with the RAM position**: the two player positions recorded in `re4-switch-ram.md`, (-3809.2, 41.6, 5961.0) and
  (-3668, 41, 6021), fall on a **floor cell of r400** (Village) and outside the grid of r402, r403 and r404. SAT floor height at both is
  0.0 mm; RAM y is 41.6 / 41 mm, so RAM y sits ~41 mm above the SAT floor (foot offset or hover, not determined). x and z are the same frame
  for r400 as far as these 2 samples show. For r402, r403, r404 **not determined** (no RAM positions recorded for them in the repo docs
  that the ticket points at; one live position sampled in each room would settle it). A third sample, x = 50,689 (nav note; its room
  label is not verified), is outside r400's x range and inside r403's (27,703 .. 88,786) only.

## Scene cross-check (floor triangles must lie under where the bot walks)
Method: the scene's world-space triangles (SMD instances x HD model positions through `Instance.matrix`, as in `re4_stage_greybox.measure`)
with normal.y >= 0.7; for each SAT floor triangle (normal.y >= 0.5) its centroid (x,z) is tested against every scene upward triangle,
and the vertical distance to the nearest containing one is taken.

| room | SAT floor tris | centroid has a scene up-surface | within 100 mm of one (count) | within 100 mm (area) |
|---|---|---|---|---|
| r400 Village | 172 | 0.76 | 0.08 | 0.03 |
| r402 Castle | 249 | 1.00 | 0.51 | 0.43 |
| r403 Base | 383 | 0.97 | 0.66 | 0.72 |
| r404 Waterworld | 158 | 1.00 | 0.94 | 0.97 |

Reading: Waterworld agrees to the millimetre (median dy 0). Base agrees for two thirds, Castle for half. **Village does not**: the median
nearest scene surface is 3.8 m above the SAT floor, i.e. the scene has many roofs/terrain at other heights over the same x,z and the nearest
match is not the walked surface; whether the Village SAT is offset or only the test is confused by stacked levels is **not determined**
(would be settled by sampling the bot's y while walking at several Village spots). The grid below is 2D and collapses stacked levels.

## The grid and the walls
Per room (json `walk_grid`): origin = floor-snapped min x,z of all vertices; 250 mm cells; row 0 is the smallest z, column 0 the smallest x;
`cells` is rows x cols characters, row-major, no separators. A cell is `.` if its centre lies under a SAT triangle with normal.y >= 0.5 (floor
or slope up to 60 degrees), `#` if a wall segment crosses a cell that has floor (the segment is sampled every 62.5 mm), or the centre lies
under a wall triangle with no floor, else a space. Several storeys are merged. Walls (`wall_segments_mm_x0_z0_x1_z1`): triangles with
|normal.y| < 0.5 and max y - min y > 1,000 mm, projected to a segment along the triangle's horizontal tangent; duplicates removed.
The `#`/wall rules are the ticket's thresholds applied to this slot; they are method choices, not game data.
