# Exact-title reusable asset work

`GET /api/title-assets/{game_id}` shows durable extraction jobs and coverage for characters, props, textures and animations. It uses the exact catalog ID; same-named editions and platforms do not share results. The catalog key invalidates old work when the library ID, relative path, catalog hashes, size or launch source change. Per-worker mount paths are resolved from current configuration at execution; configuration-only path changes require explicit inventory refresh. That key is an invalidation hint, not a verified source digest.

`POST /api/title-assets/{game_id}/collect` accepts `categories`, optional `worker_id`, `parent_request_id`, `request_ids`, `retry_failed` and `allow_unpack`. Every linked request must already exist. Repeated calls share the same jobs across dependent builds; each call advances at most one bounded raw extraction job. A finite coordinator can poll the returned job IDs and call collect again after completion. No periodic resolver, launch, task-mode change or build completion is implied.

For registered Sonic, Mario and Twin Snakes readers, character collection continues through the existing `characters collect` tool on a Linux collection worker. Its scope is the registered roster subset. Separate props, textures, animation coverage and exact source revision remain unverified unless a reader and evidence explicitly support them. This endpoint does not convert roster counts into full-title coverage.

The exact-title route preserves its selected Linux source worker through ordinary job submission. Other character-collection submissions retain their existing Linux scheduling behavior. Native export continuation follows explicit worker-alias records after a worker restarts; it never guesses another machine from a matching title. Job claims still enforce normal permissions, idle time, resource measurements and operator-session protection.

For the curated DOA3 USA catalog identities, the `title_assets` worker tool first inventories the source and then exports non-placeholder `loadfile.afs` members in chunks of at most 128 members and 24 MiB. It prefers the existing per-title native play-disc view, checks its receipt against the actual executable and AFS bytes, and never reads the save tree. An existing catalog extraction can also be reused. Unpacking an archive requires explicit `allow_unpack:true`; there is no full-ROM staging call or image-extractor installation. The cache promotion hook must retain its busy guard while skipping generic full-title promotion for `title_assets`.

Inventory and export manifests retain game ID, catalog key, actual XBE/AFS SHA-256, member indices/names/hashes, source worker and job ID. Export source hashes must match the prior inventory. A catalog change after queueing or an AFS change before/during export fails the job rather than attaching it to an older revision.

If owned source bytes change while catalog metadata stays the same, collect with `refresh_inventory:true` explicitly starts a new durable inventory epoch. This is refused while any title extraction job is queued or running. Earlier jobs and exports remain in history but cannot contribute coverage to the new epoch. Retry alone retains the prior inventory revision; refresh is the deliberate recovery path for source changes.

Each raw export publishes `title-assets-native.zip` through the existing authenticated artifact API. It contains the native manifest and selected native bytes, has a 32 MiB upload limit, and is independently checked for exact member identities, paths, sizes and SHA-256. Status returns each `bundle_url`; consumers on another PC can download the artifact without depending on the producing worker's local directory. Original model/sprite collections and the asset browser are unchanged.

Raw exports explicitly report `decoded:false`, `writable:false`, `reimportable:false` and `full_character_replacement:false`. A completed raw coverage count covers only non-placeholder members of this one AFS archive. Oversized members remain listed as pending. It does not establish full-disc inventory, decoded or rigged fighters, costume completeness across chunks, cross-game retargeting, a native cast writer, or a playable build. Each requested cast variant remains pending until its own writer, source assets, build and runtime checks succeed.
