# Roadmap and milestone status

## Milestone M2: DGX Spark deployment, full library, play/inspect/Blender (2026-10-05)

Test suite: `python -m pytest -q` → **35 passed**. That includes a live check that every mapped core has a linux/aarch64 build.

### Verified on the real systems

| Area | Evidence |
|---|---|
| The Spark provisions itself (`gbox setup` / `provision_node` job) | apt packages, fstab NAS mounts (with a backup), VirtualGL, libretro RetroArch 1.22.2, cores, BIOS, Ghidra 12.1.4 and the systemd service all report ok |
| GPU rendering | each session reports `Renderer: NVIDIA GB10/PCIe` (it was CPU llvmpipe before VirtualGL) |
| Library: HyperSpin + GC ISOs | 63,728 games from 398 configs/romlists. Case-duplicate folders are merged and stale entries pruned. Search ~0.6 s/page |
| Games run, stream and take input | PSO Ver.2 (Dreamcast/Flycast), PSO Ep I&II Plus (GameCube/Dolphin), Super Mario 64 (parallel_n64), Amy Rose/Sonic (Genesis), Mario Bros (NES/Mesen). Start presses reach the game |
| Streaming | 53–55 fps to the browser/app (was ~6). One streaming upload per session, long-polled input |
| Memory | Flycast RAM through `READ_CORE_RAM` (native `0x8C000000` translated), GameCube MEM1 (disc ID `GPOE8P` read back), NES writes through the core memory map with rollback bytes kept |
| Inspector | live session RPC for RAM and ROM reads; ROM tiles decoded (real Mario CHR sprites) |
| Blender bridge | `open_in_blender` on Blender 5.3 alpha: validated .blend artifact. The gBox add-on pastes clipboard images as pixel-exact planes in real Blender |
| Compatibility sweep | partial run: chailove, Channel F and ColecoVision verified as running and drawing. A full run is still pending |

### Known limits

- RetroArch's control interface doesn't expose CPU registers, breakpoints, disassembly or VRAM. The Inspect view says so instead of faking them.
- The stream is MJPEG with no audio, about 5–8 MB/s during busy scenes. Next step: H.264 over WebRTC (check for NVENC on the GB10) plus audio.
- The MAME romset is 0.228 while the libretro `mame` core is current, so some sets may fail. The sweep and per-game status show which.
- Systems without an ARM64 core run on the Windows node through RocketLauncher. That launch path is built but not yet exercised on a real game.
- Sessions are children of the gbox service, so restarting the service (update/relaunch) ends running games.

### Written but NOT verified (missing tools on the build host)

- `open_in_blender` + `clients/blender/gbox_bridge.py`: Blender isn't installed. The tool reports itself unavailable, as tested.
- `analyze_binary` + `adapters/ghidra/ExportAnalysis.java`: Ghidra isn't installed. Current Ghidra releases need JDK 21; this host has JDK 17.
- RetroArch adapter against a real RetroArch + Flycast build. Whether Flycast exposes memory to `READ_CORE_MEMORY` is unverified.
- `Dockerfile` (Linux / DGX Spark, arm64): the Docker daemon wasn't running, so it was not built.

### Not implemented

- **Phase 1 exit (launch, view and control remotely)** isn't met. There's no emulator installed and no per-button `send_input`. Plan: use Sunshine (already installed on this host) + Moonlight for remote view/control of the session, and add RetroArch network-remote input for automated control.
- Phase 2 (PSO V2 instrumentation): needs RetroArch+Flycast and an operator-supplied PSO V2 image.
- Phase 3 (autoplay), Phase 4 (Ghidra bridge beyond export), Phase 6 (live picker), Phase 7 (environment extraction, FBX/ABC, Godot/Unreal recipes, retargeting), Phase 8 (mod builder), Phase 9 (cross-title), Phase 10 (more adapters).
- Streaming audio, breakpoints, execution tracing, memory map query.
- Windows packaged build (PyInstaller is available; not done yet).

### Storage generated
